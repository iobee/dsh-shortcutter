# DSH Shortcutter · 0.1.22

DSH 的独立导航插件。以导航面板承接单键和组合键，调用现有插件的动作；不修改或替换官方插件。

面向 macOS Desktop，当前按本机 **DSH 0.2.1-rc.2** 验证。

项目与包名统一为 `dsh-shortcutter`，界面名称为 **Shortcutter**。0.1.22 是改名版本，延续原有导航行为和圆点样式。为兼容已保存的用户设置，内部返回导航命令 ID `magic-shortcuts.navigate` 和本机存储键 `dsh.magic-shortcuts.v1` 保持稳定；它们不作为界面名称展示。

## 开始使用

- **Esc**：从左侧栏或对话返回导航；弹窗、菜单、输入法先处理自己的 Esc。对话生成中保留 DSH 的双 Esc 停止输出，此时用 ⌘ J 返回导航。
- **⌘ J**：从终端、网页或其他区域返回导航，对话和左侧栏也可使用。
- **点击右侧顶部**：点击工具标签返回导航；浏览器地址工具栏的空白处也可使用。输入框、标签改名、按钮、拖动和菜单保留原操作。
- **i**：进入当前对话、终端或网页，随后按键由内容处理。
- **Esc（导航中）**：取消当前组合键或收起提示，仍停留在导航态。终端和网页中的 Esc 保持原行为。
- **?**：收起或展开导航提示。
- **默认导航**：普通页面和设置页没有输入框聚焦时即为导航态；输入框聚焦后退出，失焦后恢复。无需额外点一次空白，恢复时不弹出 which-key。尊重“自动导航”开关。
- **g → s**：打开 DSH 设置，与 **⌘ ,** 使用同一设置入口。导航面板右上角齿轮也打开 DSH 设置；修改插件配置时，在设置左侧选择 **Shortcutter**。

默认打开后进入导航态，面板左上角的小点表示当前导航目标。which-key 平时隐藏，按 g 后显示并等待第二键；执行动作、取消或输入无效第二键后收起。也可按 ? 主动查看提示，执行其中的动作后同样收起。组合键依次按下，不需要同时按住。导航层以物理字母键识别，Shift 区分大小写；输入法组合期间不处理单键。

| 默认键位 | 动作 |
| --- | --- |
| s | 展开 / 收起左侧栏 |
| c | 回到对话；右侧全屏时先恢复面板 |
| r | 展开 / 收起工具面板 |
| e | 打开文件面板，复用当前会话的已有标签 |
| b / t | 在当前会话已打开的浏览器 / 终端间循环切换，保持导航态；没有时提示使用大写新建 |
| B / T | 新建浏览器 / 终端，保持导航态；按 i 或点击内容进入输入 |
| w | 关闭当前导航指向的工具标签，关闭后继续保持导航态 |
| n | 新建会话，使用与 DSH 原生 ⌘ N 相同的入口 |
| R | 放大 / 恢复右侧停靠面板 |
| g → a | 上一个会话；连续使用可往返 |
| [ / ] | 上一个 / 下一个右侧工具标签，按标签栏顺序循环并保持导航态 |
| g → s | 打开 DSH 设置 |
| ? | 展开 / 收起 which-key 提示 |

设置中可改普通单键和 g 序列、取消某项绑定或关闭自动导航。返回导航组合键通过 DSH 官方快捷键服务保存，冲突会提示并保留原配置。其余设置保存在当前 DSH 窗口来源的 localStorage（`dsh.magic-shortcuts.v1`），不与其他设备同步。配置升级为 v3，仍使用原存储键。旧默认 g t / g T 分别迁移到 ] / [；自定义或已取消的标签切换绑定保持不变。旧默认 Space s 迁移到 g s，Space n / Space ? 退役；自定义 Space 组合取消绑定并在设置页提示。其余自定义键位及自动导航选项保留；新增 B / T 或迁移 g s 遇到已有自定义绑定时让出键位。加载时不写回，保存后更新原数据。

## 焦点边界

默认在打开应用、切换会话、或通过插件快捷键切换工具后尝试进入导航态。后台加载时等待第一次激活；鼠标直接点击终端、网页或输入框则直接使用内容。切换后等待公开会话 / 终端就绪状态，再进行一次焦点交接；不会持续把焦点抢回来。

0.1.8 按当前输入焦点判断默认导航：包括设置页、按钮聚焦、输入框失焦、页面切换和输入控件移除。观察状态不会主动 focus/blur 控件，不修改草稿或文字选择。设置页内的文字输入与对话输入使用相同规则。终端、网页、代码编辑器、审批控件、菜单和普通确认弹窗继续保留原操作；设置页内新打开的菜单/弹窗也优先。按钮和复选框的 Space、Enter、Tab 保持原生行为。关闭自动导航后仍可用显式返回导航快捷键。

0.1.9 修复输入法组合状态残留导致单键无响应：原输入控件失焦、移除或窗口失活后，清理插件内部尚未结束的组合状态，按当前焦点重新判断导航。输入法仍在原控件中组合时继续让出按键，宿主自己的输入法与控件优先判断保持不变。焦点视觉、which-key、终端、网页和菜单操作不变。

0.1.10 补齐 demo 中的 `n` 新建会话，通过 DSH 公开的 `uiWorkspace.startSession()` 使用当前工作区打开新会话，保留已有会话与草稿。旧配置自动补充这一绑定；若已有自定义动作使用 `n`，保留原绑定，新建会话暂不绑定，可在插件设置中另选键位。显式取消的绑定不会被恢复。`Space → n` 仍是切换自动导航。

0.1.11 将快捷键设置移入 DSH 原生设置侧栏的 **Shortcutter** 项，不再使用独立的快捷键设置弹窗。`Space → s` 和提示面板齿轮直接打开该项；保存后留在当前设置页，可以继续编辑。配置存储、键位、冲突校验、焦点视觉与 which-key 行为保持不变。录制快捷键时切换设置项或关闭设置会自动结束录制。

0.1.12 将 `Space → s` 和提示面板齿轮改为打开 DSH 设置，不再直达插件配置。关闭时打开宿主默认设置页；设置已经打开时保留当前设置项。插件配置仍通过设置侧栏的 **Shortcutter** 进入。已有自定义键位与其他交互保持不变。

0.1.13 去掉 Space 前缀层，g 专用于跳转，? 查看提示；自动导航仅在设置中调整。b / t 复用当前会话最近使用的同类标签，重复按不会切换到另一个或重复创建；鼠标选择、原生标签切换和插件导航共用记录。最近标签关闭后回到仍存在的上一个；记录在插件重新加载后重建，初次以当前选中标签优先。B / T 始终新建，只对这次新建执行一次输入焦点交接；用户点击别处、切换输入控件 / 标签 / 会话或打开菜单后取消交接。g t / g T 按可见标签栏顺序切换，未显示的标签排在后面。

0.1.14 小写 b / t 只操作已打开的同类标签：从其他区域进入时回到最近使用的标签，在该工具区域继续按则沿标签栏顺序循环，最后回到第一个。一个标签时停留原标签，没有标签时提示使用 B / T 新建，不自动创建。大写新建、默认导航、which-key 显隐和焦点视觉均沿用上一版。

0.1.15 增加 w 关闭当前工具标签，配合 b / t 循环使用。调用 DSH 原有标签关闭 / 清理入口，关闭后停在宿主选中的剩余标签，并继续导航；工具面板收起后回到对话导航。在对话、左侧栏、设置或工具收起时不关闭后台标签，过期目标也不回退到另一个标签或应用窗口。输入框、终端和网页内部仍正常输入 w。旧配置补充默认 w；已有自定义 w 时保留原用途，新关闭动作为未绑定，显式取消和自定义关闭键位均保留。

0.1.18 将 B / T 新建后的焦点交接改为返回导航，按 i 或点击内容再开始输入。自动导航开启时，点击右侧标签及浏览器地址工具栏空白，也在宿主完成本次点击后返回导航。鼠标拖动、双击改名、地址输入、原生按钮、菜单及弹窗不接管；切换会话或继续操作会取消尚未完成的交接。点击先保留宿主的标签身份，宿主替换标签栏 DOM 后仍按原标签完成交接；已关闭、切换会话或身份过期时取消。已有终端要等待视图重新挂载并完成自身聚焦后再交接。每次只交接一次，不持续抢焦点；焦点视觉与 which-key 显隐规则不变。macOS 顶部用于拖动整扇窗口的空白区域不向插件发送鼠标点击，继续用于拖窗；返回导航请点标签标题或按 ⌘ J。

0.1.19 将上一个 / 下一个工具标签的默认键位改为 [ / ]，跨浏览器、终端、文件等所有右侧标签，沿标签栏顺序循环并首尾回绕。切换后等待当前目标准备好，再保持导航态。旧默认 g T / g t 迁移为新键位；自定义和显式取消保留，升级后仍可手动改回旧组合。输入框、网页、终端内容、菜单及带修饰键的原操作不变，Shift + [ / ] 不触发标签切换。焦点视觉和 which-key 显隐规则不变。

0.1.20 将焦点提示改为当前面板左上角的固定小圆点：直径 5 CSS px，距左边和上边各 6 px；亮色 #59616b、暗色 #a1a5ad，透明度均为 0.8。沿用确认的角点预览，移除旧细线和柔光，不闪烁、不做位移或亮度动画。导航状态、快捷键和 which-key 显隐逻辑保持不变。

收起按键提示仍保留圆点；按 i、点击输入控件或工具内容、打开菜单/其他模态窗口或应用失去焦点时隐藏。设置页的圆点位于设置面板左上角。标记位于插件自己的透明覆盖层，只读取宿主面板边界，不修改各面板的标题、背景、标签或内容，不阻挡点击。配色跟随宿主解析后的亮暗主题。

导航命令单键在导航态的普通页面及设置页生效，不要求 DOM 焦点留在插件锚点。设置页中按导航命令离开时，通过宿主公开接口关闭设置层；按 i 聚焦当前设置页的首个输入框。左侧栏、对话中未被原控件处理的 Esc 可返回导航，使用现有 `observeFixedInput` 在本地控件之后处理；对话生成中不接管 Esc。只有返回导航组合键通过官方原生快捷键服务注册。插件不向终端发送控制序列、不注入网页、不替换输入组件或键盘处理器。

DSH 目前没有统一的工具聚焦接口：终端和浏览器的 `i` 使用限定到当前会话及面板的可见 DOM 焦点适配；`c` 读取右侧面板的全屏标记后调用官方恢复动作。圆点只读取布局与面板的 DOM 位置绘制，不修改宿主节点。适配失败时保留原界面行为，不尝试控制组件。DSH 升级后需要复验这些标记。

## 首版限制

- 自动导航不是宿主提供的原子操作，内容准备过程仍可能存在短暂焦点空隙；无法保证快速连按时绝无漏键。可在设置里关闭自动导航，改为显式 ⌘ J。
- 原组件重新聚焦输入框时会退出导航；焦点留在普通控件或页面时自动导航。悬浮 / 拆分面板仍需要单独复验。
- 文件区只提供打开与切换；尚不提供内部键盘导航。`i` 对文件区域会提示点击进入。
- 搜索、hjkl、网页字母标签和按数字跳转标签不在本版范围。
- “上一个会话”是本窗口本次插件运行期间的历史，重载后重新开始记录。

## 安装与禁用

开发源码位于 `src/`，回归测试位于 `test/`；构建会生成 `lib/` 和 `dist/`。仓库保留 `dsh-shortcutter.html` 交互原型和 `artifacts/focus-markers-study/` 焦点方案预览，二者用于设计参考，不代表生产插件的全部行为。早期实验、日常应用截图和本机安装记录保留在本地，不纳入仓库。

构建并生成本地安装包：

```sh
npm run build
npm test
npm pack --ignore-scripts --pack-destination dist
```

从旧包升级时，先通过同一官方 CLI 移除 `dsh-magic-shortcuts`，再安装下方的新包。两个包共用兼容设置，不应同时启用。旧包移除不会删除本机快捷键偏好；本项目此次改名保留这些设置键。如果运行中的窗口仍显示旧名设置项，在当前任务结束后正常退出并重新打开 DSH，以加载更名后的插件组合。

```sh
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" \
  plugin --profile desktop remove dsh-magic-shortcuts
```

macOS 官方桌面应用自带的安装入口（普通 npm 安装的 `dsh` 不管理 desktop profile）：

```sh
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" \
  plugin --profile desktop add /绝对路径/dsh-shortcutter-0.1.22.tgz --offline --ignore-scripts
```

插件声明独立 `dsh.bundle`，仅追加 `shortcutter` 条目。安装包只包含生产代码、包清单、bundle patch 和本文档，不含测试探针或原型。无运行依赖、安装脚本或网络请求。

在 DSH 的 **Plugins / 插件** 页面搜索 `dsh-shortcutter`，可以关闭整个插件包，或禁用它的 `shortcutter` 条目。禁用会移除提示面板、单键监听和返回导航注册，保留设置以便重新启用。

卸载可使用插件页面，或官方桌面入口：

```sh
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" \
  plugin --profile desktop remove dsh-shortcutter
```

## 开发与验证

`src/core.js`：键位校验和序列状态机。`src/client.js`：插件及焦点交接。`src/tool-tabs.js`：工具标签历史、标签顺序和新建交接边界。`src/default-navigation.js`：输入焦点与模态范围的状态观察。`src/tool-navigation.js`：工具顶部点击的导航交接。`src/blank-navigation.js` 保留为 0.1.7 历史回归模块，不再进入构建。`src/styles.css`：独立样式。`scripts/build.mjs` 将它们合成 DSH client 模块；Host 入口为空。

本机 `verification/` 保留早期隔离验证工具、应用截图与安装记录，不上传源码仓库、不进入安装包。仓库中的 `npm test` 不依赖这些本机记录，可独立运行。
